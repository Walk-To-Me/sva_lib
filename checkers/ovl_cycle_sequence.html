ovl_cycle_sequence — 逐拍事件序列

周期、窗口与稳定性 OVL V2 接口

把 event_sequence 的各位视为事件，按高位到低位在连续周期内匹配。

语义参数端口例子FormalSVA 属性来源

1. 检查语义与触发时机

necessary_condition 选择“前 N-1 项匹配才要求末项”或“首项发生就要求后续全部”；PIPE/NOPIPE 决定能否重叠。

MOST_PIPE 下中间前提未成立可能不失败；必须选对触发模式并覆盖完整序列。

以下说明以随包 SVA 实现为重点。复位后的首次有效采样、历史状态有效位以及 generate 条件会影响检查起点；属性原文与完整源码可在本页下方对照。

2. 完整参数表

按 wrapper 声明顺序列出。默认表达式逐字取自源码；宏的最终值可被编译选项或用户头文件覆盖。标为内部/派生参数的条目不建议手动覆盖。

参数源码默认值作用与配置注意
severity_level`OVL_SEVERITY_DEFAULT失败报告的严重级别：OVL_FATAL、OVL_ERROR、OVL_WARNING、OVL_INFO；不是改变逻辑正确性的开关。
num_cks2检查周期数或精确延迟；cycle_sequence 中同时决定事件向量长度。
necessary_condition`OVL_NECESSARY_CONDITION_DEFAULTMOST_PIPE=0：匹配前 N-1 项才要求最后一项；FIRST_PIPE=1：首项触发全部后续且可重叠；FIRST_NOPIPE=2：首项触发且不流水重叠。
property_type`OVL_PROPERTY_DEFAULT选择 OVL_ASSERT、OVL_ASSUME、OVL_IGNORE 或二态变体；只有支持的后端才把 ASSUME 实现为形式约束。不要把 DUT 要求改为 assume 来消除失败。
msg`OVL_MSG_DEFAULT实例的诊断文本，建议包含被检查接口与需求名称。
coverage_level`OVL_COVER_DEFAULT覆盖层级位掩码；NONE=0、SANITY=1、BASIC=2、CORNER=4、STATISTIC=8、ALL=15。同时受 OVL_COVER_ON 控制。
clock_edge`OVL_CLOCK_EDGE_DEFAULTchecker 的时钟有效沿：OVL_POSEDGE、OVL_NEGEDGE 等；各后端支持情况需核对。
reset_polarity`OVL_RESET_POLARITY_DEFAULT复位有效电平：OVL_ACTIVE_LOW 或 OVL_ACTIVE_HIGH；不要因端口名为 reset 就默认高有效。
gating_type`OVL_GATING_TYPE_DEFAULTOVL_GATE_CLOCK 暂停时钟采样；OVL_GATE_RESET 用 enable 参与复位；OVL_NONE 不使用门控。暂停与清空历史不是同一语义。
assert_name"OVL_CYCLE_SEQUENCE"内部诊断标识。源码注明不应修改。

3. 完整端口表

端口方向位宽表达式连接含义
clockinput1 bit采样时钟；有效沿由 clock_edge 决定。
resetinput1 bitchecker 复位输入；有效电平由 reset_polarity 决定。
enableinput1 bitOVL V2 门控输入，意义由 gating_type 决定；不一定只是 disable iff。
event_sequenceinput[num_cks-1:0]按高位至低位排列的逐拍事件向量。
fireoutput[`OVL_FIRE_WIDTH-1:0]事件汇总输出；部分 wrapper 在 SVA 分支将其绑零，见本页实现提示。

4. 合法与违例场景

合法 / 期望覆盖场景

四项序列为 1xxx→x1xx→xx1x→xxx1。

违例 / 覆盖缺口场景

FIRST_PIPE 下首项发生后第二拍第二项缺失。

示例中的周期指 checker 的有效采样沿；“变化”通常指相邻采样值变化。场景是语义说明，不代表下面保留默认参数的模板已配置成该场景。

5. Formal 接入与判读

MOST_PIPE 下中间前提未成立可能不失败；必须选对触发模式并覆盖完整序列。

  • 验证 DUT 的要求使用 OVL_ASSERT；只有外部环境协议才适合作为 OVL_ASSUME。先检查 elaboration 后生成的属性数量与类型。
  • 复位应初始化 checker 的历史状态和参考模型；不要永久拉住复位或 enable=0。确认触发事件可达，避免 antecedent 永远为假的空证明。
  • 将安全断言结果、超时/未决结果与 cover 可达性分别记录。仿真跑过若干波形不等于形式证明。

fire 的驱动由所选实现与宏决定；输出端口存在并不保证每种后端都提供相同汇总行为。核对 wrapper 和后端，formal 优先读取原生属性。

更多复位、门控、X/Z 与编译宏说明见 公共接入指南。本页没有声称所有配置均在 VC Formal 上经过编译或证明。

6. 属性、诊断与覆盖

下面是源码中的命名 property 定义，包含宏分支；同名属性可在互斥 generate 分支中出现。它们不是“全部同时启用”的断言清单。实际启用条件、参考状态更新及 assert/assume 实例请看完整源码。

ASSERT_SEQUENCE_TRIGGER_ON_FIRST_P
property ASSERT_SEQUENCE_TRIGGER_ON_FIRST_P;
    @(posedge clk)
    disable iff (`OVL_RESET_SIGNAL != 1'b1)
      not (&((seq_queue[NUM_CKS_1:1] & event_sequence[NUM_CKS_2:0]) |
           ~(seq_queue[NUM_CKS_1:1]))) != 1'b1;
  endproperty
ASSERT_SEQUENCE_TRIGGER_ON_MOST_P
property ASSERT_SEQUENCE_TRIGGER_ON_MOST_P;
    @(posedge clk)
    disable iff (`OVL_RESET_SIGNAL != 1'b1)
    seq_queue[1] |-> event_sequence[0];
  endproperty
ASSERT_SEQUENCE_TRIGGER_ON_NC0_NC1_FIRST_EVENT_XZ_P
property ASSERT_SEQUENCE_TRIGGER_ON_NC0_NC1_FIRST_EVENT_XZ_P;
      @(posedge clk)
      disable iff (`OVL_RESET_SIGNAL != 1'b1)
      !$isunknown(event_sequence[NUM_CKS_1]);
    endproperty
ASSERT_SEQUENCE_TRIGGER_ON_NC2_FIRST_EVENT_XZ_P
property ASSERT_SEQUENCE_TRIGGER_ON_NC2_FIRST_EVENT_XZ_P;
      @(posedge clk)
      disable iff (`OVL_RESET_SIGNAL != 1'b1)
      ((!(|seq_queue[NUM_CKS_1:1])) || $isunknown((|seq_queue[NUM_CKS_1:1]))) |->
      !$isunknown(event_sequence[NUM_CKS_1]);
    endproperty
ASSERT_SEQUENCE_TRIGGER_ON_NC1_NC2_SUBSEQUENT_EVENTS_XZ_P
property ASSERT_SEQUENCE_TRIGGER_ON_NC1_NC2_SUBSEQUENT_EVENTS_XZ_P;
      @(posedge clk)

      !$isunknown((^(seq_queue[NUM_CKS_1:1] & event_sequence[NUM_CKS_2:0])));
    endproperty
ASSERT_SEQUENCE_TRIGGER_ON_NC0_NON_LAST_EVENTS_XZ_P

原始失败诊断文本

以下文本便于与工具报告交叉查找，触发条件见上面的对应属性和源码分支。

  • First num_cks-1 events occured but they are not followed by the last event in sequence
  • First event occured but it is not followed by the rest of the events in sequence
  • First event in the sequence contains X or Z
  • Subsequent events in the sequence contain X or Z
  • First num_cks-1 events in the sequence contain X or Z
  • Last event in the sequence contains X or Z
