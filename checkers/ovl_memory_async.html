ovl_memory_async — 访问边沿驱动的存储检查

FIFO、栈与存储器 OVL V2 接口

以 ren/wen 的配置边沿作为读写事件，检查地址、初始化与可选数据值。

语义参数端口例子FormalSVA 属性来源

1. 检查语义与触发时机

没有独立 clock 端口；wen_edge/ren_edge 选择访问边沿。value_check 默认关闭；同时访问同地址按原实现的先读后写关系理解。

这是异步接口事件模型，不是异步 FIFO/CDC 或亚稳态检查器；formal 对事件时钟的支持需单独确认。

以下说明以随包 SVA 实现为重点。复位后的首次有效采样、历史状态有效位以及 generate 条件会影响检查起点；属性原文与完整源码可在本页下方对照。

2. 完整参数表

按 wrapper 声明顺序列出。默认表达式逐字取自源码；宏的最终值可被编译选项或用户头文件覆盖。标为内部/派生参数的条目不建议手动覆盖。

参数源码默认值作用与配置注意
severity_level`OVL_SEVERITY_DEFAULT失败报告的严重级别：OVL_FATAL、OVL_ERROR、OVL_WARNING、OVL_INFO；不是改变逻辑正确性的开关。
data_width1存储器数据宽度；CRC 中为完整数据项宽度，0 表示采用输入 width。
addr_width1存储器地址位宽。
mem_size2参考存储器可跟踪的位置数；需覆盖使用的地址范围。
addr_check1开启地址在 start_addr/end_addr 范围内的检查。
init_check1开启读地址已写入/初始化的检查；不是清零 DUT 存储器。
one_read_check0限制同一数据项重复读；需要读写历史，不是限制每拍读端口数。
one_write_check0限制数据未按协议读取前重复写；不是写使能只能维持一拍。
value_check01 开启参考数据一致性检查，0 不做数据值比较；FIFO 与 memory 的默认值不同。
property_type`OVL_PROPERTY_DEFAULT选择 OVL_ASSERT、OVL_ASSUME、OVL_IGNORE 或二态变体；只有支持的后端才把 ASSUME 实现为形式约束。不要把 DUT 要求改为 assume 来消除失败。
msg`OVL_MSG_DEFAULT实例的诊断文本，建议包含被检查接口与需求名称。
coverage_level`OVL_COVER_DEFAULT覆盖层级位掩码；NONE=0、SANITY=1、BASIC=2、CORNER=4、STATISTIC=8、ALL=15。同时受 OVL_COVER_ON 控制。
wen_edge`OVL_CLOCK_EDGE_DEFAULT写访问的有效边沿，memory_sync 针对 w_clock，memory_async 针对 wen。
ren_edge`OVL_CLOCK_EDGE_DEFAULT读访问的有效边沿，memory_sync 针对 r_clock，memory_async 针对 ren。
reset_polarity`OVL_RESET_POLARITY_DEFAULT复位有效电平：OVL_ACTIVE_LOW 或 OVL_ACTIVE_HIGH；不要因端口名为 reset 就默认高有效。
gating_type`OVL_GATING_TYPE_DEFAULTOVL_GATE_CLOCK 暂停时钟采样；OVL_GATE_RESET 用 enable 参与复位；OVL_NONE 不使用门控。暂停与清空历史不是同一语义。
assert_name"OVL_MEMORY_ASYNC"内部诊断标识。源码注明不应修改。

3. 完整端口表

端口方向位宽表达式连接含义
resetinput1 bitchecker 复位输入；有效电平由 reset_polarity 决定。
enableinput1 bitOVL V2 门控输入，意义由 gating_type 决定；不一定只是 disable iff。
reninput1 bit同步版本为读使能；异步版本其有效边沿就是读事件。
weninput1 bit同步版本为写使能；异步版本其有效边沿就是写事件。
start_addrinput[addr_width-1 : 0]有效地址闭区间起点。
end_addrinput[addr_width-1 : 0]有效地址闭区间终点。
raddrinput[addr_width-1 : 0]读地址。
rdatainput[data_width-1 : 0]按 checker 采样点提供的读出数据。
waddrinput[addr_width-1 : 0]写地址。
wdatainput[data_width-1 : 0]写入数据。
fireoutput[`OVL_FIRE_WIDTH-1 : 0]事件汇总输出；部分 wrapper 在 SVA 分支将其绑零，见本页实现提示。

4. 合法与违例场景

合法 / 期望覆盖场景

地址 a 写 A 后，独立读事件返回 A。

违例 / 覆盖缺口场景

init_check 开启时先读未初始化地址，或数据检查开启后读错。

示例中的周期指 checker 的有效采样沿；“变化”通常指相邻采样值变化。场景是语义说明，不代表下面保留默认参数的模板已配置成该场景。

5. Formal 接入与判读

这是异步接口事件模型，不是异步 FIFO/CDC 或亚稳态检查器；formal 对事件时钟的支持需单独确认。

  • 验证 DUT 的要求使用 OVL_ASSERT；只有外部环境协议才适合作为 OVL_ASSUME。先检查 elaboration 后生成的属性数量与类型。
  • 复位应初始化 checker 的历史状态和参考模型；不要永久拉住复位或 enable=0。确认触发事件可达，避免 antecedent 永远为假的空证明。
  • 将安全断言结果、超时/未决结果与 cover 可达性分别记录。仿真跑过若干波形不等于形式证明。

参考队列/存储器会扩大状态空间。先使用小 depth、短数据宽度验证接线，再扩大参数；如采用任意地址/任意数据抽象，需单独证明抽象保持原需求，不能仅减少被检查的数据。

此 wrapper 的 SVA 分支将 fire 绑为 0。不能用 fire==0 证明检查通过；必须读取工具中的原生 assert/assume/cover 结果。

更多复位、门控、X/Z 与编译宏说明见 公共接入指南。本页没有声称所有配置均在 VC Formal 上经过编译或证明。

原始失败诊断文本

以下文本便于与工具报告交叉查找，触发条件见上面的对应属性和源码分支。

  • data read is not same as data written
  • uninitialized location is read
  • write address is not within range of start and end address
  • read address is not within range of start and end address
  • data is not read before it is overwritten
  • there is more than 1 read between 2 successive writes
  • start address contains X or Z
  • end address contains X or Z
  • read address contains X or Z
  • read data contains X or Z
  • write address contains X or Z
  • write data contains X or Z
