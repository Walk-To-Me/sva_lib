公共接入与 Formal 指南

OVL 是可复用的断言和检查模型库；仿真与 formal 可以复用需求表达，但执行方式与结果含义不同。

1. Formal scoreboard 与仿真 scoreboard

维度仿真Formal
输入轨迹只检查 testbench 实际激励的有限轨迹。在约束和初始化模型下探索所有可能轨迹；有界结果只覆盖相应深度。
参考模型可使用队列、事务对象、动态内存和软件算法。参考状态必须能被形式引擎建模；动态结构、覆盖统计及规模可能成为限制。
数据一致性对实际入队/出队事务比较预期值。同样维护参考关系，但要证明所有可达状态下成立。可使用任意元素抽象，需额外证明抽象正确。
结果无报错表示已运行轨迹未发现错误。PROVEN 只针对选定属性及当前模型；FAIL 给出反例，UNKNOWN/超时不是通过。
空通过测试未触发检查常表现为覆盖不足。约束过强、复位不释放、触发不可达都会产生无意义证明，需 cover 和非空验证。

2. 选择 checker

先写清楚需求的采样点和触发条件，再选模块：布尔不变量用 always/implication，编码用 one_hot/mutex，定点延迟用 next，窗口稳定用 unchange/win_unchange，协议用 handshake/req_ack_unique，数据顺序用 fifo/multiport_fifo，只有容量需求用 fifo_index。

OVL 不自动知道 DUT 的 valid/ready 语义。例如 FIFO 参考模型一般接 wr_accept = wr_en & !full、rd_accept = rd_en & !empty；如果设计允许满时同时出入或空时旁路，需要按接口规范重新定义 accept，并匹配 registered/pass_thru。只看接受操作可证明状态与数据，但不能额外证明“请求永不被拒绝”。

3. 编译与宏

编译 SV harness、所需 ovl_*.v wrapper，并把 OVL 根目录加入 include path。wrapper 会 include 对应后端，不要重复编译被 include 的逻辑文件。以下是适用于二态形式检查的起始选项，不是通用且已验证的 VC Formal Tcl：

+incdir+<OVL_ROOT>
+define+OVL_SVA+OVL_ASSERT_ON+OVL_SYNTHESIS+OVL_XCHECK_OFF
<OVL_ROOT>/ovl_fifo.v
<YOUR_FORMAL_HARNESS>.sv

OVL_SVA 选择 SVA 实现，OVL_ASSERT_ON 打开相应逻辑，OVL_SYNTHESIS 用于屏蔽不适合综合/形式前端的部分报告代码；其具体屏蔽范围应看头文件。OVL_XCHECK_OFF 会改变/关闭 X/Z 检查，不能用于声称已证明无未知值。不要同时定义多个互斥后端宏。

OVL_COVER_ON 可能引入 covergroup 或过程式覆盖，工具未必接受。可先关闭 OVL 内建覆盖，再在 harness 写显式 cover property；需要库内覆盖时，单独验证支持情况与 coverage_level。编译成功后仍要确认检查属性真的生成。

4. 公共参数与默认宏

参数本发行包未覆写的默认值说明

property_type`OVL_ASSERT选择 OVL_ASSERT、OVL_ASSUME、OVL_IGNORE 或二态变体；只有支持的后端才把 ASSUME 实现为形式约束。不要把 DUT 要求改为 assume 来消除失败。

5. 复位、时钟与 enable

V2 reset 默认低有效，名称没有 _n 也不代表高有效。复位极性参数只解释 checker 输入，不会替你设置 formal 初始状态。工具需要正确建立时钟、复位序列和历史状态；具体命令随 VC Formal 版本及应用模式而变化。

OVL_GATE_CLOCK 的 enable=0 暂停采样与历史推进；OVL_GATE_RESET 把禁止状态用于复位；OVL_NONE 忽略 enable。它们不等价。memory 的双时钟与无时钟 checker 不应照搬单时钟设置。实际 SVA 的 disable iff 和内部参考状态复位还应一起检查。

6. assert、assume 与 cover

assert 是 DUT 要满足的性质；assume 是允许的输入环境。不要把 DUT 的 full/empty、数据顺序或响应保证假设为真。约束只加入真实接口协议，随后覆盖复位释放、请求接受、队列满/空、同时读写、指针回绕等关键情形。

// Illustration: adapt clock/reset and acceptance expressions.
cover property (@(posedge clk) disable iff (!rst_n) wr_accept);
cover property (@(posedge clk) disable iff (!rst_n) full);
cover property (@(posedge clk) disable iff (!rst_n) wr_accept && rd_accept);

不能只查看 fire。标准位含义为 fire[0] 功能失败、fire[1] X/Z 失败、fire[2] 覆盖事件，但本版多个 SVA wrapper 将 fire 绑零。优先查看原生 property 的证明状态、具体 generate 层级与失败轨迹。

7. 参数与规模验证建议

  1. 确认所有信号宽度、延迟、同拍事件顺序，以及 0 的特殊含义。
  2. 使用小规模配置先做可达性和预期违例检查；故意制造一个错误，确认能产生反例。
  3. 检查环境假设和复位释放，确认每类 antecedent 可以触发。
  4. 扩大深度、宽度和 outstanding 数量；超时单独记录，不当作通过。
  5. 对每个目标配置保存源码版本、宏、参数、工具版本和结果；仅验证一个参数实例不能证明所有参数化实例。
