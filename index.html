OVL checker 分类与使用手册

55 种 V2 checker，8 个功能类别，33 个旧版兼容接口。

面向 RTL / formal 使用者的中文离线手册。每个模块包含语义、完整参数与默认值、端口、正反例、接线模板、形式验证注意点和实际 SVA 属性。范围限定为你提供的 OVL 2.8.1（April 2014）；不同语言文件是同一 checker 的不同实现，不重复计数。

最容易遗漏的配置：multiport_fifo、memory_sync、memory_async 的 value_check 默认关闭；部分 SVA wrapper 的 fire 绑零；code_distance 的 SVA 检查汉明距离，和手册数值差文字不一致。

布尔条件与事件采样 5 个

Checker用途关键语义
ovl_always恒真条件每个有效采样沿要求 test_expr 为真。
ovl_always_on_edge边沿限定的恒真条件根据 sampling_event 的采样变化决定是否检查 test_expr。
ovl_implication同拍蕴含antecedent_expr 为真时，要求同拍 consequent_expr 为真。
ovl_never禁止条件每个有效采样沿要求 test_expr 不为真。
ovl_proposition组合恒真命题不使用 clock，在表达式变化的组合语义下检查 test_expr。

位编码、互斥与数据完整性 12 个

Checker用途关键语义
ovl_bits有效位数量范围统计 test_expr 中为 1 或为 0 的位数，要求数量落在 min 到 max 之间。
ovl_code_distance两向量的汉明距离本版 SVA 使用 $countones(test_expr1 ^ test_expr2)，要求不同 bit 的数量在 min/max 闭区间内。
ovl_even_parity偶校验要求 test_expr 中 1 的个数为偶数，零个 1 也满足。
ovl_odd_parity奇校验要求 test_expr 中 1 的个数为奇数。
ovl_one_hot严格独热编码要求 test_expr 恰好只有一个 1。
ovl_zero_one_hot零或独热编码允许全部为零，或恰好只有一个 1。
ovl_one_cold独零编码要求恰好只有一个 0，并可配置额外 inactive 编码。
ovl_mutex可反相的互斥检查默认最多一个 bit 为 1；invert_mode=1 时最多一个 bit 为 0。
ovl_never_unknown采样时无未知值qualifier 为真时，要求 test_expr 所有位为 0 或 1。
ovl_never_unknown_async组合无未知值无 clock 输入，以异步/组合方式检查 test_expr 不含 X/Z。
ovl_no_contention总线争用与空闲间隔检查 driver_enables 不允许多驱动，并按配置检查总线未知值和 quiet 间隔。
ovl_crcCRC 参考计算与比较内部计算 CRC，并在 compare 触发时与输入校验值比较。

数值范围与变化步长 7 个

Checker用途关键语义
ovl_range数值闭区间每个有效采样沿检查 min <= test_expr <= max。
ovl_increment变化时固定递增只有 test_expr 相比上一拍变化时，才要求按 value 递增。
ovl_decrement变化时固定递减只有 test_expr 变化时，才要求按 value 递减。
ovl_delta变化步长范围test_expr 变化时，检查两个方向的定宽模差至少一个位于 min/max 范围。
ovl_no_overflow上边界后的防回绕上一拍等于 max 时，对下一拍值进行上边界检查。
ovl_no_underflow下边界后的防回绕上一拍等于 min 时，对下一拍值进行下边界检查。
ovl_value允许/禁止值集合比较 test_expr 与 vals 中的候选值列表，disallow 决定允许集合还是禁止集合。

周期、窗口与稳定性 11 个

Checker用途关键语义
ovl_change限时至少变化一次start_event 启动后，要求 test_expr 在随后 num_cks 个采样周期内至少变化一次。
ovl_unchange限时保持稳定start_event 启动后，要求接下来 num_cks 拍保持 test_expr 稳定。
ovl_time固定周期恒真窗口start_event 后的 num_cks 拍要求 test_expr 每拍为真。
ovl_next精确延迟响应start_event 为真后，恰好 num_cks 拍后的 test_expr 必须为真。
ovl_frame有上下界的响应窗口在 start_event 的采样上升沿附近建立响应检查，min/max 控制过早和超时条件。
ovl_width高电平脉冲宽度检查 test_expr 连续为真的采样周期数是否满足 min_cks/max_cks。
ovl_hold_value指定值的驻留时间test_expr 变化到与 value 相等时，检查该值保持的时间。
ovl_win_change事件窗口内至少变化start_event 保存 test_expr 后，从下一拍到 end_event 关闭窗口时检查是否发生过变化。
ovl_win_unchange事件窗口内稳定从 start_event 建立参考后，到 end_event 所在关闭拍要求数据不变。
ovl_window事件窗口内恒真start_event 后开启窗口，要求窗口内每个有效采样沿 test_expr 为真。
ovl_cycle_sequence逐拍事件序列把 event_sequence 的各位视为事件，按高位到低位在连续周期内匹配。

状态转移与寄存器传递 5 个

Checker用途关键语义
ovl_transition强制下一拍状态test_expr 等于 start_state 时，保存当拍 next_state，要求下一拍 test_expr 等于它。
ovl_no_transition禁止下一拍状态test_expr 等于 start_state 时，保存当拍 next_state，禁止下一拍进入该值。
ovl_next_state驻留时间与后继集合test_expr 变化到 curr_state（或首个有效周期匹配）时，启动驻留周期和后继状态集合检查。
ovl_quiescent_state事件发生时的目标状态sample_event 的采样上升沿上，要求 state_expr 等于 check_value。
ovl_reg_loaded限时寄存器传值start_event 上升时捕获 src_expr，要求 dest_expr 在指定窗口出现该值。

握手、仲裁与事务 ID 5 个

Checker用途关键语义
ovl_handshake单事务请求应答协议根据 req/ack 的采样上升事件追踪握手，并检查参数指定的响应期限与电平持续规则。
ovl_req_ack_unique流水请求与唯一应答每拍 req=1 生成一个 outstanding 请求，每个有效 ack 按 FIFO 顺序匹配最早请求。
ovl_req_requires四事件依赖链检查 req_trigger、req_follower、resp_leader、resp_trigger 的顺序和完成时间窗口。
ovl_arbiter仲裁策略与授权时限联合检查多路 reqs/gnts、授权合法性、响应时间与可选优先级/仲裁策略。
ovl_valid_id带 ID 的未完成事务追踪发出、返回和 flush 的事务 ID，检查返回合法性、容量和时间约束。

FIFO、栈与存储器 6 个

Checker用途关键语义
ovl_fifo单端口 FIFO scoreboard内部参考队列检查先入先出数据、满空标志与溢出下溢。
ovl_fifo_indexFIFO 占用量边界只根据 push/pop 数量维护参考占用量，检查上下溢，不保存数据。
ovl_multiport_fifo多端口 FIFO scoreboard检查每拍多路入队/出队的队列容量、可选标志和数据顺序。
ovl_stackLIFO 栈 scoreboard内部参考栈检查后入先出数据、满空标志和容量边界。
ovl_memory_sync同步存储器参考检查分别在 r_clock/w_clock 有效沿观察 ren/wen，检查地址、初始化及可选数据一致性。
ovl_memory_async访问边沿驱动的存储检查以 ren/wen 的配置边沿作为读写事件，检查地址、初始化与可选数据值。

覆盖采集与交叉覆盖 4 个

Checker用途关键语义
ovl_coverage布尔事件覆盖用于收集 test_expr 为真的事件；其断言采用反向意义，事件发生可能故意使断言失败。
ovl_value_coverage取值覆盖与排除列表采集 test_expr 的取值变化/覆盖，并支持 is_not 排除列表。
ovl_xproduct_bit_coverage位交叉覆盖记录一个或两个向量的位对同时为 1 是否曾发生。
ovl_xproduct_value_coverage数值交叉覆盖记录两个表达式的目标取值组合是否曾经出现。
