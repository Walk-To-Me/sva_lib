assert_handshake — 单事务请求应答协议

握手、仲裁与事务 ID 旧版接口

根据 req/ack 的采样上升事件追踪握手，并检查参数指定的响应期限与电平持续规则。

语义参数端口例子FormalSVA 属性来源

这是保留兼容用途的旧接口，不是新增一种检查语义。使用旧版专属端口表和模板；不能只把模块名称替换为 ovl_*。查看对应 V2 说明。旧接口复位由 std_ovl_defines.h 宏选择，未暴露 V2 的 clock_edge/reset_polarity/gating_type 参数。

1. 检查语义与触发时机

每个 ack 必须有待处理 request；前一事务未完成时不允许新的请求事件。req_drop、deassert_count、max_ack_length 决定请求保持、撤销和 ack 脉宽规则。

这是请求应答协议检查器，不等于 ready/valid；ready 可以预先为高，不能直接作为该 checker 的 ack。

以下说明以随包 SVA 实现为重点。复位后的首次有效采样、历史状态有效位以及 generate 条件会影响检查起点；属性原文与完整源码可在本页下方对照。

按 wrapper 声明顺序列出。默认表达式逐字取自源码；宏的最终值可被编译选项或用户头文件覆盖。标为内部/派生参数的条目不建议手动覆盖。

参数源码默认值作用与配置注意
severity_level`OVL_SEVERITY_DEFAULT失败报告的严重级别：OVL_FATAL、OVL_ERROR、OVL_WARNING、OVL_INFO；不是改变逻辑正确性的开关。
min_ack_cycle0请求到 ack 的最小周期延迟。
max_ack_cycle0请求到 ack 的最大周期延迟；0 关闭该最大等待检查。
req_drop0大于 0 时开启请求保持检查：req 上升后必须持续为高直到 ack 上升；0 不生成这一保持属性。名称不能理解为 1 允许提前撤销。
deassert_count0ack 上升且 req 仍高时，要求 req 在随后 0..deassert_count 拍内拉低；0 不生成该期限属性。
max_ack_length0ack 高电平的最大周期宽度，0 关闭该项上界。
property_type`OVL_PROPERTY_DEFAULT选择 OVL_ASSERT、OVL_ASSUME、OVL_IGNORE 或二态变体；只有支持的后端才把 ASSUME 实现为形式约束。不要把 DUT 要求改为 assume 来消除失败。
msg`OVL_MSG_DEFAULT实例的诊断文本，建议包含被检查接口与需求名称。
coverage_level`OVL_COVER_DEFAULT覆盖层级位掩码；NONE=0、SANITY=1、BASIC=2、CORNER=4、STATISTIC=8、ALL=15。同时受 OVL_COVER_ON 控制。
assert_name"ASSERT_HANDSHAKE"内部诊断标识。源码注明不应修改。

4. 合法与违例场景

合法 / 期望覆盖场景

发出一个请求，在允许窗口内出现一个 ack 上升沿。

违例 / 覆盖缺口场景

无请求时 ack，或 pending 时再次产生请求上升。

示例中的周期指 checker 的有效采样沿；“变化”通常指相邻采样值变化。场景是语义说明，不代表下面保留默认参数的模板已配置成该场景。

5. Formal 接入与判读

这是请求应答协议检查器，不等于 ready/valid；ready 可以预先为高，不能直接作为该 checker 的 ack。

  • 验证 DUT 的要求使用 OVL_ASSERT；只有外部环境协议才适合作为 OVL_ASSUME。先检查 elaboration 后生成的属性数量与类型。
  • 复位应初始化 checker 的历史状态和参考模型；不要永久拉住复位或 enable=0。确认触发事件可达，避免 antecedent 永远为假的空证明。
  • 将安全断言结果、超时/未决结果与 cover 可达性分别记录。仿真跑过若干波形不等于形式证明。

更多复位、门控、X/Z 与编译宏说明见 公共接入指南。本页没有声称所有配置均在 VC Formal 上经过编译或证明。

6. 属性、诊断与覆盖

下面是源码中的命名 property 定义，包含宏分支；同名属性可在互斥 generate 分支中出现。它们不是“全部同时启用”的断言清单。实际启用条件、参考状态更新及 assert/assume 实例请看完整源码。

ASSERT_HANDSHAKE_ACK_MIN_CYCLE_P
property ASSERT_HANDSHAKE_ACK_MIN_CYCLE_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $rose(req) |-> (!($rose(ack))) [*min_ack_cycle];
  endproperty
ASSERT_HANDSHAKE_ACK_MAX_CYCLE_P
property ASSERT_HANDSHAKE_ACK_MAX_CYCLE_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $rose(req) && (!$rose(ack)) |->
  (##[1:(max_ack_cycle > 0 ? max_ack_cycle : 2)] ($rose(ack) || ($rose(req) && (req_drop == 1'b1))));
  endproperty
ASSERT_HANDSHAKE_ACK_MAX_LENGTH_P
property ASSERT_HANDSHAKE_ACK_MAX_LENGTH_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $rose(ack) |-> (ack)[*1:(max_ack_length > 0 ? max_ack_length : 2) ] ##1 (!ack);
  endproperty
ASSERT_HANDSHAKE_REQ_DROP_P
property ASSERT_HANDSHAKE_REQ_DROP_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $rose(req) |-> (req[*1:$]) ##0 $rose(ack);
  endproperty
ASSERT_HANDSHAKE_MULTIPLE_REQ_P
property ASSERT_HANDSHAKE_MULTIPLE_REQ_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  not (($rose(req) && !ack) ##1 (req && !ack) [*0:$]
  ##1 (!req && !ack) [*1:$] ##1 ($rose(req)));
  endproperty
ASSERT_HANDSHAKE_REQ_DEASSERT_P
property ASSERT_HANDSHAKE_REQ_DEASSERT_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  ($rose(ack) && (req)) |-> (##[0:deassert_count](!req));
  endproperty
ASSERT_HANDSHAKE_ACK_WITHOUT_REQ_FIRST_REQ_P
property ASSERT_HANDSHAKE_ACK_WITHOUT_REQ_FIRST_REQ_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $rose(ack) |-> (first_req || req);
  endproperty
ASSERT_HANDSHAKE_ACK_WITHOUT_REQ_SUBSEQUENT_REQ_P
property ASSERT_HANDSHAKE_ACK_WITHOUT_REQ_SUBSEQUENT_REQ_P;
  @(posedge clk)
  disable iff (`OVL_RESET_SIGNAL != 1'b1)
  $fell(ack) |-> $rose(req) within (!ack [*0:$] ##1 ack);
  endproperty
ASSERT_HANDSHAKE_REQ_XZ_P
property ASSERT_HANDSHAKE_REQ_XZ_P;
    @(posedge clk)
    disable iff (`OVL_RESET_SIGNAL != 1'b1)
    !$isunknown( req );
    endproperty
ASSERT_HANDSHAKE_ACK_XZ_P
property ASSERT_HANDSHAKE_ACK_XZ_P;
    @(posedge clk)
    disable iff (`OVL_RESET_SIGNAL != 1'b1)
    !$isunknown( ack );
    endproperty

原始失败诊断文本

以下文本便于与工具报告交叉查找，触发条件见上面的对应属性和源码分支。

  • Acknowledge asserted before elapse of specified minimum min_ack_cycle cycles from request
  • Acknowledge is not asserted within specified maximum max_ack_cycle cycles from request
  • Duration of continuous asserted state of acknowledge violates specified maximum ack_max_length cycles
  • Duration of continuous asserted state of request violates specified deassert_count cycles
  • Request is deasserted before acknowledgement arrives
  • New request arrives before previous request is acknowledged
  • Acknowledge arrives without a pending request
  • req contains X or Z
  • ack contains X or Z

  • cover_req_asserted
  • cover_ack_asserted
